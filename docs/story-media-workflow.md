## 使用路径

1. 打开剧本工作室，选择单集 → **镜头媒体**。每页10镜，可刷新节点状态和本机模型列表。
2. 核对“待复制提示词”，选择图片/视频模型，点击 **建立图片/视频节点（不发送）**。确认后应用全部草稿，并在原工作室旁建立一个标准 `ai-image` / `ai-video` 节点。
3. **关闭并定位原生成节点**，在原节点核对模型、账号配置、参数、媒体输入和费用，再显式点击原生成按钮。这里没有另一套生成按钮、自动提交或自动重试。模型清单可用不等于账号或厂商在线。
4. 结果返回后重新打开工作室 → 镜头媒体 → 刷新。显示原节点保存的状态，列出成功返回中的本地原媒体；单项失败、远程结果、无本地原文件路径不被当作可采纳项。
5. 先在原节点查看实际图片/视频，再点击 **采纳结果 N 并应用**。确认会应用所有草稿、创建一个独立 `source-image` / `source-video` 结果节点，并把它关联到当前稳定镜头 ID。一个镜头最多关联一张图片和一段视频。
6. 使用**原有工程保存**落盘。工作室“应用”及 Ctrl/Cmd+S 不等于磁盘保存。重开需同时保留工程和引用的媒体文件。已采纳源节点可以沿用第10批本地媒体导出、第11批视频时间线导出或原画布媒体流程；本批不自动组装/渲染成片。

“关闭并定位”沿用画布 `v2FocusOnNodes` / `v2FocusOnNode`，不自动丢弃未应用编辑；有草稿时仍走原关闭确认。缺少定位服务时明确提示，不假报已跳转。

## 输入与生成边界

- 只复制所选镜头 `imagePrompt` / `videoPrompt`，空白时回退到画面描述；1–20000字符。复制前转义富文本，不能把文字中的HTML变成引用 pill。
- 不自动拼人物/场景文字，不自动传人物图、场景图、已采纳图片、参考媒体、边或任意参数。视频时长/尺寸等以原生成节点配置为准，不自动套用镜头目标时长。
- 初始模型来自现有 manifest：模型/执行清单均匹配厂商、image/video、modelApi，允许文字、静态输入槽不强制额外媒体。动态参数条件和实际输入要求仍由原节点校验；不是全厂商或全工作流支持承诺。
- 创建时重新核对模型身份，只写 `{provider, model}` 与指定文字，不复制模板节点的 API Key、服务地址、任意请求参数或媒体引用。原生成入口仍在执行时读取原账号/服务设置；用户在原节点主动配置媒体或改参数仍遵循原流程。
- 每次只创建一个节点，同镜同类最多保留6个生成节点；这是防误建限制，**不是媒体队列**，不是厂商幂等/计费上限。重建、原节点再次生成可能再次收费。
- 第12批单镜状态页只读节点内的状态/结果，不查询厂商、不启动恢复或取消。第12批当时未改原恢复逻辑；第13批仅对新批次标记阻止图片缺taskId的自动fallback重提，保留其他原流程；“running”可能是恢复待核对的旧记录，关闭、刷新、停止都不保证厂商停止执行或计费。

## 稳定归属与结果保存

- 已有 `episode.id`、`shot.id` 本来就是稳定 ID，本批复用而不另造镜号身份。生成节点保存 `storyMediaSource`：版本1、工作室节点ID、单集ID、镜头ID、本节点ID、媒体类型和复制时的提示词。
- 所有匹配同时检查上述ID；普通克隆生成节点若保留旧来源中的 nodeId，不会冒领为新的镜头任务。重排镜头不改变归属；复制单集生成新ID，并清除 `mediaRefs`，不继承原镜头结果。
- 提示词或回退描述改变后，旧任务仍可定位，但不允许按原来源采纳。其他未发送字段（例如时长、对白）改变不构成提示词冲突；原AI节点中人工修改提示词/配置被视作这个任务的人工变体，采纳前仍须查看实际结果。
- 只接受 `jobStatus === success` 且不在生成中的结果。图片读 `images`、视频读 `videos`，保留真实数组索引；没有集合时使用原节点结果字段。最多100项，超限整组提示而非静默截取。
- 选择记录包含节点ID、结果索引、本地路径、generationStartTime（兼容旧generationStartedAt；第13批修正）；点击采纳时重读，变化即拒绝。模型目录删除或离线不阻止已有结果采纳。
- 只认本地原媒体，复用 `normalizeLocalPath` 和第10批路径/扩展名白名单：`data/assets/`、`data/uploads/`、`output/`。图片优先 originalLocalPath，不能用缩略图悄悄替换坏的原图；视频不把封面当视频。远程、blob/data/file、绝对路径或类型不符结果不采纳。
- 采纳创建独立标准源媒体节点，白名单只带本地路径、展示字段及 `storyMediaResult` 来源。**不复制文件字节，不检查文件是否存在，不做文件内容哈希。** 原生成节点再次生成/被删除不会自动改变已采纳节点的路径，但同一路径文件若被外部覆盖或删除，本批不能保护字节内容；需要另外备份/导出。
- `shot.mediaRefs` 是工作室v1的可选扩展字段，仅 `{kind,nodeId}`，最多两个且类型不重复；既有 normalize 白名单、JSON导入导出和4MiB总量校验已接入。不内嵌媒体文件。
- 已关联节点丢失、来源不符、其路径被更换、提示词变旧都会提示，不静默清除/替换。更换同类关联保留旧源节点；“解除关联”只改草稿，不删节点/磁盘文件。独立工作室JSON跨画布导入不会搬媒体或自动重连；旧版工作室代码可能丢弃这个新增字段。

## 应用、工程和冲突

`applyStoryWorkspaceDraft` 复用原 store 与 history，先检查捕获的 nodes 对象身份、工作室类型、baseSignature、完整草稿容量及新节点ID/类型/来源，再写入。创建或采纳与草稿应用共用一个 history commit；普通无变化应用不会新增历史。

这是同步预检，不是跨 store/磁盘原子事务；若原 store 或 commit 抛错，不能声称自动回滚。原工程保存的权限、磁盘失败及重开仍需运行验收。未增加默认自动保存，也不改第七至九批文字队列检查点/恢复规则。

已静态核对 `CanvasTabManager.getMultiDataSnapshot({sanitizeForPersistence:true})` → `thumbnailPersistence.sanitizeMultiCanvasDataForPersistence`：现有节点序列化保留新来源标签和工作室字段。新增测试源码使用真实 sanitizer 与 JSON roundtrip，**尚未执行，不代表真实工程保存/重开已通过**。
