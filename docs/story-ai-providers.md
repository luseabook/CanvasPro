# 第九批：剧本 AI 多厂商文本模型

把现有文本生成能力接入剧本 AI 助手和串行分镜队列。不是新增另一套 HTTP 客户端、密钥库或厂商 SDK，也不复制新版整个模型运行时。

## 使用入口

- 剧本工作室 → AI 助手：拆集、资料提取、生成分镜共用厂商/模型选择器。
- 剧本工作室 → 批量 AI 分镜队列：先选择厂商及模型，再建立批次。**更改下拉选择不会修改已有任务的厂商或模型**；需要更换时，先导出原记录，再建立新批次。

选择器先保留原火山引擎默认模型（清单有效时），再收集当前画布文本/分镜节点以及本机已注册文本模型；按“厂商 + 模型 ID”去重，同名不同厂商不会合并。切换厂商会重选该厂商的第一项，请在发送确认中核对。

## 接入范围

| 厂商标识 | 模型来源与要求 |
| --- | --- |
| `volcengine` | 原默认分镜模型及本机文本清单，保留 `volcengine/` 标识 |
| `agnes`、`apimart`、`grsai`、`ppio` | 本机已注册、支持纯文字的文本 modelApi 模型 |
| `runninghub` | 文本 LLM 的 chat-completion 清单；排除图片必选 CV/image-to-text 和工作流 |
| `openai`、`custom` | 当前画布 `ai-text` / `storyboard-script` 节点中已有的显式模型 ID；不虚构模型列表，不新增任意 URL 输入框 |

普通厂商要同时满足：模型和执行清单厂商一致、均为 `text` / `modelApi`、输出为文本、允许文字输入、不要求图片/视频/音频等额外输入，以及执行模式为现有适配器支持的 `chat-completion` 或 `responses`。不把异步属性误当成一定可用或不可用；按实际输入与执行模式筛选。

**OpenAI/custom 是兼容模式例外**：没有可验证的本机模型清单，仅校验 ID 格式，并沿用已有文本 API 的 OpenAI 兼容路由。`custom` 使用的也是 **OpenAI 配置**，不是新的独立账号。离线不能判断自定义 ID 是否存在、是否具备文本能力、账号权限或结构化输出能力。

此处接入的是本项目已有厂商，不代表任意新增厂商、CLI 厂商、工作流或多模态任务已经补齐。

## 调用与隐私边界

- 继续调用 `api/aiTextApi.js` 的 `generateText`，复用原有配置加载、请求映射、代理、鉴权和响应处理。没有改动该文件、原 manifest 或后端代理。
- 密钥/服务地址由原有设置管理，在真正执行时读取；模型出现于选择器不代表账号已配置、厂商在线或可成功输出合格 JSON。
- 如果配置了中转，文字会发送到该配置服务，不一定是厂商官方直连。执行前请核对设置，队列执行期间不要切换账号或服务地址。本批不冻结这些设置。
- 请求适配只复制厂商、模型 ID、任务提示词和系统提示词；媒体数组明确为空。不复制节点/快照中的 API Key、URL、额外生成参数、媒体引用或任意请求头。
- 正文、所选文字资料和模型结果可能含敏感信息；白名单不是对正文内容的脱敏保证。模型返回仍须人工审阅。
- 单次助手、队列、不同厂商仍使用同一个页面内占用锁；切换厂商不能绕过正在等待的请求。该锁不是跨页面/跨浏览器/厂商端去重服务。
- 无自动换厂商、降级模型、重试、自动修复 JSON 或自动追加镜头。某些现有厂商客户端可能在一次逻辑调用内执行原有查询流程；逻辑调用次数不等于 HTTP 次数或账单次数。

## 队列与本地保存兼容

快照继续使用 `canvas-story-ai-queue.v1`，模型只保存 `{provider, model}`。旧火山引擎快照可按原规则恢复；新增厂商快照**不能保证被第七/八批旧代码导入**，需要更新后的源码。未知厂商、无效模型标识仍整体拒绝导入，不部分覆盖。

模型身份的存储校验与运行时可用性检查分开：本机清单删除某模型后，旧结果仍能恢复、审阅和导出，不应因为无法再次调用就丢失已付费结果。

创建批次、发送确认、逐项发送前和最终请求适配层都会核对模型。队列发送前已不可用的模型被阻止，不自动改成默认模型；进入队列 preflight 的失败不增加该项尝试次数。保存等待后也会重新检查。配置或网络失败仍可能只得到“状态待核对”，不保证未执行/未计费。

第八批规则不变：明确启用本地保存；保存失败暂停后续发送；恢复后待发送项变待核对、在途项变未知；不自动重发。新批次覆盖/清空也会更新已启用的本地副本，必须先备份旧结果。
