# 第20批：明确启用的本机媒体任务历史与只读取回

更新：2026-09-23。R03 **有限源码检查点，未运行验收**。接在原 `MediaTaskQueue`、任务中心、第16批四类本地结果的显式取回之后；不替代队列、不恢复执行、不查询厂商，也不将历史记录并入工程包。

## 使用入口与开关

- 原任务中心下方新增折叠的“本机历史记录”。默认不记录。用户主动读取状态，再明确确认“启用记录”；暂停也要明确确认。`configure` 带当前宿主 sessionId/controlRevision，过期设置被拒绝；读/查询/展开面板不写入记录或重发任务。
- 历史宿主文件位于既有 `STORAGE_ROOTS.storageRoot/MediaTaskHistory/history.json`：源码模式是工程 `user-data/` 下，发布版使用用户可写的既有 files 根；**不是安装包资源目录**。IPC 仅接受主应用窗口的主 frame/本地应用 URL，不接受渲染进程给出的磁盘路径。
- 本进程默认关闭；已明确写盘的 `enabled` 开关会随宿主重启读取。启用前或宿主关闭期间的旧任务不自动回填。原队列仍在内存，清理原界面的已完成卡片不会清除历史文件。
- 状态区分别显示本进程启用状态和最近成功写盘的开关/时间、`pending`、记录/跳过/淘汰数及存储错误。超时或失败只表示未取得成功回执，不承诺操作一定未发生；请重新查状态，勿直接重试任务。

## 数据边界与故障处理

- JSON v1 是有上限的**摘要日志**：最多1000条/8MiB。记录只含随机记录ID、宿主会话ID、任务/原节点ID、kind、状态与有限时间；仅四类已核实本地成功结果保留 `output/` 虚拟路径及视频时长/尺寸/帧率或音频时长。**不复制**任务 payload、提示词、密钥、服务地址、错误详情、原始厂商响应、媒体字节或原工程。路径/文件名和任务ID本身仍可能涉及隐私，启用前请确认本机存储策略。
- 同taskId的新原生任务对象有独立 recordId；按原生任务对象更新摘要，不把重用taskId的结果混成一个任务。磁盘修订0只代表“尚无文件”的内存初值，不能作为已保存的启用凭据。容量淘汰优先最旧的已终止或旧宿主进程记录，不淘汰本进程未终止记录；空间不够时跳过并标明，而非改写任务状态。
- 写盘使用独占锁、读取版本摘要对比、临时文件、重命名及读回核对；已有损坏/不支持版本、外部改动、链接/占用/磁盘故障时不覆盖原文件、不将失败当成功。崩溃留下的锁不自动删除；应人工确认没有其他实例和原始数据后再处理。不是多机同步、不可变审计日志或抗恶意本机管理员的安全边界。
- 只读历史查询仅返回**已成功写盘**的记录，最多单页50项，可按确切任务ID或 recordId 查询；内存中的未写盘结果不是历史回执。宿主重启后旧 `waiting` 显示 held、旧 `processing` 显示 unknown，**不会**重新入队、调用 handler、发回旧任务事件、假装厂商已取消或任务完成。

## 人工结果取回

- 只有 `storySequenceExport`、`mediaClipExport`、`videoReverse` 的成功 MP4 与 `audioCompose` 的成功 MP3 可人工取回；历史记录还必须完整、已写盘、明确完成。列表中展示其它状态只是待核对线索。原结果文件是否仍存在/被替换未探测，也不借原nodeId推断画布或镜头归属。
- 人工选中**具体 recordId** 后，第16批取回流程会在确认前、确认后两次对同一持久记录只读核对结果与当前画布，并新建独立source媒体节点。选择另一个记录、关闭任务中心或切画布会使旧响应失效；不得把同taskId第一条记录代替指定记录。不自动改旧节点、不关联工作室、不复制文件；添加后仍须手动使用原工程保存。旧流程已添加同一路径但无取回标签时不跨画布/全局去重，请先核对。
- `mediaTaskRecovery` 字段仅带第16批来源白名单加 `historyRecordId/historySessionId`；不是已渲染媒体存在性证明，也不是宿主任务恢复凭据。普通原任务中心查询/取回以及其它旧任务的原自动回写语义不因本批改变。

## 第25批增量：本地结果原画布门禁（2026-09-24）

- 入队前在渲染器捕获活动画布ID及原生store的`nodes`对象，并提前预留本进程任务ID；相同ID不覆盖其他渲染器关联。宿主回执必须返回相同ID，否则提示任务状态不确定，**不自动重试/取消**。回写节点时不仅看nodeId或assetId，还必须保持原画布及原nodes对象；250ms进度合并后再次核对。直接`wait:true`路径在交还结果前也核对，避免剪辑/合成等原调用方往另一画布创建节点。结束事件释放关联；渲染进程重启后的旧宿主任务关联缺失，禁止自动回写。
- 切走再返回原画布时原store已hydrate为新nodes对象，故本批保守地**不自动回填**。宿主结果仍可能存在，支持的四类媒体通过原任务中心按明确ID/记录ID人工取回；其他任务结果需核对原输出，不要盲目重新跑。该防误写门禁不证明调用前来源、同画布节点重建、HTTP后备任务、厂商AI请求或费用已处理；不提供真正跨画布后台执行/持久队列/厂商取消。
