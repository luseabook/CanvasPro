# 第八批：队列本地自动保存与恢复

为第七批串行 AI 文字分镜队列增加浏览器 IndexedDB 本地副本。无需安装第三方包或新增后端接口；未改变模型鉴权、分镜 schema 或媒体桥接。

**不是常驻后台服务、云同步、厂商状态查询，也不保证永久备份或请求恰好执行一次。** 浏览器/应用配置文件、站点地址/端口改变，或者清理站点数据、隐私模式结束、存储驱逐、崩溃时，都可能使副本不可用。必须保留手动 JSON 备份。

## 入口

剧本工作室 → 批量 AI 分镜队列 → **本地自动保存（IndexedDB）**。

首次只检查是否存在本地记录，不自动恢复或覆盖它。明确确认后选择：

- **启用本地自动保存**：仅在当前键没有旧记录时启用。保存当前队列及后续变更，包括清空、导入和替换批次，因此这些操作也会更新本地副本。
- **恢复本地记录并启用保存**：替换当前内存队列，需要确认；导入状态沿用第七批规则，待发送变待核对，进行中变状态未知，不自动发送、不自动追加镜头。
- **重试本地保存**：只重试数据库保存，不调用模型、不自动重新排队。
- **关闭自动保存**：保留已提交的本地记录，后续生成回到内存模式，仍需手动导出；保存故障不会偷偷降级成成功。
- **删除此工作室本地记录**：关闭自动保存，仅删除绑定键的本地副本，保留内存队列和工程镜头。事先导出需要的记录。
- **导出已提交的本地副本**：导出数据库最近已提交版本，可能早于当前内存状态。原“导出队列快照”按钮则导出当前内存版本，两者不是同一时刻的保证。

启用前会说明：保存内容含正文、所选资料文字、本地引用 ID、模型标识、任务状态和模型返回文本。快照不加密，不从项目设置复制 API Key/服务地址/凭据；正文或结果本身若含敏感信息，也会保存，请自行核对和保管。共享浏览器配置文件的其他使用者或同源脚本可能访问这些记录；退出登录不自动清除它们。

## 保存语义

- 队列变更进行约300ms防抖保存；状态显示区区分未启用、有待保存变更、正在保存、事务已提交与错误，只有事务完成才视为保存成功。
- 自动保存模式下，每次模型调用前先提交“准备发送/请求中”快照，再重新检查来源及请求占用情况。**前置提交失败，不调用本项模型，并停止后续发送。**
- 请求中标记可能先于真实发送，因此恢复时不能由它推断厂商已收到或未收到。禁止自动重发。
- 模型返回后先保留结果，再提交结果状态；后置提交失败时保留内存结果、暂停后续发送，支持修复保存或手动导出，不把保存错误伪装为模型错误。
- 暂停/停止若发生在前置保存期间，不继续调用模型；若模型已经调用，仍不能保证取消执行或计费。
- 数据库提交、厂商请求、工作室草稿与工程保存是独立步骤，不构成跨系统原子事务，也不能保证幂等计费。
- 本地“已追加草稿”只记录队列状态，不证明工程已应用/保存。原工程仍需应用并保存，恢复后再次追加可能重复。

## 身份、并发与资源范围

数据库名 `canvaspro.story-ai-queues.v1`，只操作该数据库的 `queues` 表，不读取或清理其他应用数据库。

键由打开工作室时的工程 ID、现有 recent ID/工程路径/文件名线索、画布 ID、工作室节点 ID 组成。缺少稳定标识时不能启用自动保存，可先保存工程再重开工作室，或继续使用手动快照。另存、移动、改名或标识变化可能形成不同键；不自动迁移，不仅凭同名标题跨工程恢复。

来源工程/画布改变时阻止新提交和合并；已发请求的迟到结果只保存到捕获的旧键，不写入新工程。具有相同内部标识的工程副本仍需人工核对正文和资料。

启用会话使用同源 Web Locks 独占锁，并通过数据库版本令牌 compare-and-set 拒绝覆盖已改变的记录。另一个自动保存窗口不能同时获得该键；不会强夺锁。**该锁不涵盖用户明确选择的内存模式、其他浏览器配置文件或厂商端请求。** 没有 Web Locks/IndexedDB 的环境明确报错，不假称启用成功。

每条快照最多8MiB，最多32条记录、合计64MiB快照正文（UTF-8计数，不是实际磁盘占用承诺）；浏览器自身配额可能更小。达到限制、磁盘/权限错误、数据库阻塞、版本冲突或超时都会显示失败，不静默删除旧队列。请打开相应工作室导出并删除不需要的本地记录。本批不提供全局记录管理或孤立记录自动清理。若记录元数据或尺寸严重损坏，普通读取/删除入口可能失败；应先保留可导出的记录，再由熟悉开发者工具的人员检查这一专用数据库，避免清空整个站点而损失工程等其他数据。

## 关闭与刷新

返回工作室时继续保留本会话队列，已启用的保存仍有效。关闭工作室会暂停后续请求；只要页面仍活着，会等待已有请求及最后一次保存后释放锁。若关闭窗口后保存失败但页面还在，会提示是否导出仍持有的内存快照。

**这不保证关闭浏览器/退出程序后还能收到结果。** 刷新、进程终止或断电前未提交的变更及未收到的厂商响应可能丢失；不依赖 unload 中的异步保存。离开前应暂停、等待当前请求和保存结束、查看状态并导出备份。

重开原工程及工作室后，发现本地记录需要人工确认恢复；不自动恢复运行状态。未确认的请求仍应先核对厂商记录，不能以缓存状态作为计费凭据。
