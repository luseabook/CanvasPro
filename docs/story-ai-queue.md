# 多集 AI 分镜队列（第七／八／九批）

本批是工作室内的串行文字分镜队列：一次建立 1–6 个单集任务，逐项生成、保留结果、逐项审阅和确认追加。复用第六批分镜模型/预览、第五批文本 API 与单请求占用锁；不新增后端或媒体生成接口。第八批另接浏览器内置 IndexedDB 本地保存，见 `story-ai-queue-storage.md`。

不是完整的系统后台任务中心，没有常驻服务、跨设备同步或厂商幂等计费保证。第八批提供需明确启用的浏览器本地自动保存，不替代备份或工程保存。

## 使用步骤

1. 剧本工作室 → **批量 AI 分镜队列**。
2. 选择 1–6 个单集、每集 1–32 镜、厂商及文本模型（第九批扩展，见 `story-ai-providers.md`）。人物/场景文字资料默认不选；可设置共用创作要求。
3. 点击 **建立批次（尚不发送）**。所有输入和整批容量先校验，任一失败不替换现有队列。
4. 点击各项“查看”，展开待发送文字。队列保存的是建立时的输入快照，修改工作室不会悄悄改写这些任务。
5. 点击 **开始 / 继续待发送项**，确认待发送数量、每集输入长度、镜数、模型、资料数量及可能逐项产生的费用。
6. 同时只执行一个工作室队列请求。每项成功后标为“待审阅”，**不会自动追加镜头**。失败、来源冲突或无效 JSON 会暂停后续发送。
7. 查看分镜结果。要修改 JSON 或追加镜头，先暂停并等当前请求结束；本地校验不请求模型。
8. 勾选需要的镜头，确认追加到工作室草稿。返回工作室，继续 **应用到项目 → 原有工程保存**。

切换任务或重新校验会重新创建预览，勾选恢复全选，确认前需再次核对。再次打开队列时保留本会话中的任务记录，但不自动继续发送。

## 暂停、停止与重试

- **暂停后续发送**：不再开始下一项，当前请求继续等待。当前返回结果仍保留。
- **停止并跳过待发送项**：将尚未发送的 queued 项标为已跳过；不删除已返回结果，不冒称取消厂商执行。
- 请求失败或断网只能标为 **请求状态待核对**，不能断言“厂商没收到”或“未计费”。先核对厂商记录，再显式重新排队。
- 格式错误保留可显示的原始文本，可手动修正。过大返回不保存；不会自动请求“修复 JSON”。
- **重新排队**只改变本地状态，不立即请求模型。会清除该项旧返回文本，需再次开始并确认费用。
- 每项最多 3 次本地执行尝试；尝试次数不等于厂商计费次数。重建新批次不具备厂商侧防重复能力。
- 来源正文或所选设定变化、容量不足、其他工作室 AI 请求仍在等待时，在调用执行器前阻止该项，不扣本项尝试次数。
- 一个失败项不会自动重试或自动跳过继续收费。用户可显式继续其他待发送项；受阻/未知/需修正项不属于待发送项。
- 工作室之外原有画布生成通道不归这个队列管理。执行期间不要切换项目服务地址或账号配置，各项复用执行时的现有配置。

## 保存、导出与恢复边界

**队列不写入工程文件。未启用第八批本地自动保存时，仍只保留在当前工作室会话中。** 启用后将变更保存到当前浏览器的 IndexedDB，已提交的副本可人工恢复，但未提交变更和未收到的响应仍可能丢失。返回工作室会暂停后续发送；关闭/刷新前请检查保存状态并导出快照。浏览器清理、驱逐或崩溃可能导致副本不可用，不能只依赖本地缓存。

使用 **导出队列快照 JSON** 显式下载，再确认下载文件已保存。快照格式为 `canvas-story-ai-queue.v1`，最大 8MiB。内容包括输入正文、所选资料文字/本地 ID、模型标识、状态、尝试次数与返回文本；它不从账号配置复制 API Key、服务 URL 或凭据。正文/资料/返回文本本身可能含敏感信息，文件需自行保管。

恢复时：
- 打开原工作室节点，使用 **导入队列快照**；不是普通工作室 JSON 导入。
- 节点 ID 必须匹配；实际发送/合并时还会复核源单集正文和所选资料。相同 ID 的工程副本不等于同一工程，用户必须确认当前目标。
- 导入不会发送请求、不会自动追加，也不会恢复运行状态。
- 所有快照中的“待发送”项变成 **导入后待核对**，因为旧快照不能证明后来没发送。
- “请求中”变为 **请求状态待核对**。本批不能向厂商查询这些同步请求的最终状态。
- 核对后逐项重新排队，然后再次确认开始。任务由当前版本模板重建，请先预览待发送文字。
- “已追加草稿”标记保留，但**不能证明工程已应用/保存**。若原草稿确实丢失，可显式允许再次追加；原镜头若已存在会产生重复，请自行核对。
- 旧快照也可能没有记录已经完成的追加；快照可编辑，不是计费凭证、执行证明或防重复事务日志。
- 运行中导出的快照只反映导出时刻。建议暂停、等当前项返回后再导出最新快照；浏览器突然关闭前未收到的结果无法靠本批自动找回。
- 无效/超限快照整体拒绝，现有队列不被部分替换。若导出超过上限，记录仍留在窗口内，需要先自行复制结果或缩小内容；不能把失败的下载当成已保存。

来源画布卸载时暂停队列，保留有数据的工作室窗口，允许分别导出工作室草稿和队列快照；不将结果自动写入新画布。

## 结果写入和资源限制

沿用第六批段落范围、资料引用、时长与 JSON 校验。AI 内容仍需人工核对。只有选中并确认的镜头追加到原单集末尾，原正文、镜头和资料保留。确认前检查来源/容量，整体规范化后才更新草稿；不部分写入。

每批最多6项；每项32镜、正文40000 UTF-16字符/400段、提示词48000字符、返回262144字符；所选资料各20项，描述及总长度等限制沿用第六批。单集300镜、工作室2000镜、工作室4MiB限制仍然生效。每项发送和实际追加都会重新检查；手工修改容量后，先前结果未必仍能全部追加。

所有模型输入/返回、文件内容和错误提示都作为普通文本显示，不执行 HTML、脚本或文件中的请求地址。原厂商错误正文不复制到队列快照，避免保存可能夹带的凭据；请求错误统一显示状态待核对。

## 源码与验收

新增 `storyAiQueueModel.js`（批次/快照/来源校验）、`storyAiQueueRunner.js`（可注入执行器的串行状态机）、`StoryAiQueuePanel.js`（操作与逐项审阅）、两份离线测试源码。接入已有工作室编辑器和独立 CSS，不修改文本 API、原分镜 schema 或媒体桥接。

实际静态检查：目标机10个相关 JavaScript 文件通过 `node --check`，相对导入文件存在；工作室目录现有编辑器 error 诊断为0。已核对11个落地文件的目标机哈希，原文本 API、单请求占用锁、核心分镜模型和画布桥接未改动。

新增30项离线测试源码，覆盖串行、暂停/停止、重复开始、失败不重试、在途恢复、手动重排、容量/来源校验、快照白名单和已有追加标记。**测试源码未执行，未运行构建、应用或真实模型请求。** 静态检查不等于 UI 和厂商端到端验收。

手动验收：多集建立且不发请求；费用确认；串行执行；中途暂停/停止/返回；错误暂停和手工重排；与单次 AI 共享占用锁；响应 JSON 修正；逐项追加与应用保存；关闭/刷新前导出；旧/在途快照恢复；来源变更、容量不足、节点卸载；快照过大/损坏/错节点；第六批单次生成和 DOCX/PDF 导入回归。

第八批已加入明确启用的本地自动保存、检查点及恢复确认，详见 `story-ai-queue-storage.md`。第九批加入多厂商模型选择和逐项发送前模型检查；已有任务不会随下拉框改动而换厂商，新厂商快照需本批代码才能导入。

仍未补：常驻后台任务中心、云端同步、厂商状态查询与可靠远端取消、媒体批量队列、成片流程、OCR、人物替换、协作等。
