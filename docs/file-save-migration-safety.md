# 第23批：文件保存路径迁移与旧版默认目录复制的失败保护

更新：2026-09-24。**仅源码与静态检查；未执行测试套件、构建、桌面应用、真实旧工程打开/保存重开或用户文件迁移。** R14仍是部分源码，绝非全部格式与素材引用兼容验收。

## 核对现状（纠正“后端迁移不存在”的误判）

- `electron/storageRoots.js` 在安装模式区分当前 `%LOCALAPPDATA%/AI-CanvasPro/files` 与安装目录 `Data`、旧 `userData/files`；`electron/main.js` 通过 `AIC_LEGACY_*_DIR` 把可信候选传给Python。相应根逻辑、原 `fileSaveSettings.js` 和 `api/userSettingsApi.js` 与安装版只读对照SHA相同，**并不等于迁移已安全可用**。
- `server.py` 原已定义并注入迁移start/status回调给 `JsonFileRouteService`。旧行为使用 `shutil.move`，跳过同名或逐项失败后仍可切换设置；启动时还会自动移动旧默认文件。UI收到迁移start的404则直接POST保存新设置，可能让旧文件在新路径下不可见。本批修现有链路而不叠一套无后端按钮。

## 本批源码接线

1. **用户修改当前保存位置**：原“文件与保存”按钮读取当前设置并列出项目/输出/数据/上传变化；显式原生确认后，API请求带`confirmed:true`。Python同样要求确认字段。404不再回退直接写设置；一般`settings.json` POST若改变实际目录会拒绝，不能绕过复制流程；旧同步移动入口也已拒绝调用。
2. **非破坏复制与应用**：后台作业按当前项目、输出、**完整数据目录**规划，包含旧上传、资产、工作流及其他普通文件。拒绝源目标重叠/交叉、目录链接及非普通文件；以目标目录内临时文件写完/fsync，校验源哈希后独占硬链接安装，不覆盖现有目标。已有同名且内容相同只计入“相同跳过”；不同内容立即失败。再次遍历旧目录核对文件列表/元数据与目标内容；先预备新目录和服务（失败则回退内存目录），再原子替换固定用户设置（写盘失败同样回退内存目录）。设置写入与长任务合并由本机锁串行保护。**源文件与旧目录一直保留**；校验失败、磁盘满、硬链接不支持、同名冲突等不会提交新设置，但已写入的目标副本不自动删除，避免误删用户目标数据。文件修改时间与普通模式尽量保留；不保证ACL/扩展属性/空目录语义。极端的目录回退故障仍须人工检查当前设置；辅助系统设置写入失败仅记日志，不把已提交的用户设置谎报为回滚。
3. **首次升级后的旧默认目录**：取消启动时静默移动/静默重写旧路径；新增“从旧版默认目录导入”：按钮只读扫描**宿主提供的候选目录**，显示来源/目标/文件数；选择一组并再次明确确认。服务端只接受候选ID与扫描指纹，重新扫描匹配后沿同一复制/校验/进度作业复制项目、输出、数据到**当前**根，**不切换设置、不删除源**。浏览器不得传任意旧磁盘路径作为复制源。旧用户设置/API Key不导入、不复制旧宿主任务或历史。
4. 两种操作共用在进程内作业互斥和原设置迁移进度卡。保存设置写盘前合并服务器最新其他偏好，避免长复制期间覆盖无关设置；启动线程失败会移除占位任务。界面新增中英提示、失败/无法确认/旧版服务缺口的闭锁反馈；“清理旧位置”文案改为先验收旧工程与素材再单独确认。

## 边界、实际验收顺序

- **尚未转换旧项目格式或重写绝对素材引用。**复制后`.json`项目由原项目目录接口读取；`.aicanvas/.aicproj`仍走原桌面“打开工程”入口，不自动添加最近列表。旧工程节点中的绝对旧磁盘路径可能继续依赖旧文件；在真实打开、预览、另存并重开所有画布/素材前必须保留旧目录和备份，也不要使用现有“清理旧位置”动作。
- 只扫描Electron环境提供的默认旧根；自定义旧路径、丢失的安装目录、任意包/第三方格式、旧设置/密钥与历史队列不自动导入。源码不触碰实际用户文件；如果旧版程序过去已经搬动或删除过文件，本批不能凭空恢复。
- 后台作业只在当前Python进程有状态，没有持久断点、可靠取消、事务快照或重启续传。失败时旧路径/源数据保留（已成功复制的目标文件可能保留），UI短暂失联时作业仍可能继续；真正运行时须先备份并停止其他保存/生成任务。并发写入仍有最终校验与确认到应用之间的竞态，不声称字节级全局原子快照或断电完整性。
- 新接口位于原受本地令牌/Origin限制的`/api/v2/user`范围；普通磁盘复制无厂商收费请求。能否在真实NTFS、权限/UAC、只读文件/网络盘与受支持Python打包环境成功，**未验收**。
- 已写测试源码：Python纯临时目录的保留源、同名冲突/相同跳过、源变化/嵌套/链接/无硬链接、旧候选指纹过期与不可传任意源；JS路径变化与候选显示模型。**均未执行**。经用户单独授权后才用临时夹具运行离线测试，再在备份下手动验收旧`.json/.aicanvas/.aicproj`、实际素材引用、绝对路径、目标冲突、保存重开和失败恢复；构建/真实应用/用户文件复制及其风险仍需另行确认。

## 第26批增量：已有工程读取失败不得变成空白（2026-09-24）

- 原`projectService.loadProject`在`GET /api/v2/projects/<id>.json`的404、读取异常后调用`resolveCanvasData({})`；遇到不识别的对象也可能归一化为空。现用请求器的`returnMeta`保留状态，只有真实404为缺失；200/204空响应视为异常，再由`projectDocumentGuard`区分读取失败与不支持的多画布/旧单画布节点和边集合结构。默认严格；仅无URL工程ID的启动默认工程、用户在原项目管理器显式“新建”才允许404初始化空画布。真正网络/权限/损坏JSON/未知结构即使允许缺失也抛错；不转换旧素材路径。已有工程失败不会再被默默存为空白。

- 新增5项纯读取器/HTTP状态/结构判定离线测试源码，**未执行**；8相关JS仅语法检查exit0及已有编辑器error诊断0。真实旧`.json`、`.aicanvas/.aicproj`、原生/拖入文件入口、缓存恢复、格式迁移、绝对素材引用、多实例、保存重开及根切换仍需在隔离备份下单独验证，不能因本批判断为安全迁移。不要在已缺失旧工程的当前目录盲目保存新空白或清理旧文件。

## 第29批增量：恢复快照拒覆盖、条件清理与关闭确认（2026-09-24）

- 原桌面恢复快照写入会直接替换同名旧快照；保存成功后桌面与服务器两条路径会无条件删除当前快照，可能误删保存期间刚产生的新备份。本批让宿主从原始快照字节计算SHA-256修订值；`getRecoverySnapshotInfo`只为明确含`projectId`的有效正文提供身份/修订。旧快照缺明确工程ID或正文无效均标`invalid`，不自动改写。写入前要求现有快照的工程ID、最近工程路径与本次写入相符；不符或无效返回`RECOVERY_SNAPSHOT_PROTECTED`，原文件保留。条件清理必须提供捕获的工程ID和64位修订值，宿主在清理时再核对；旧无参数清理IPC不再删文件。
- 两条显式保存链路在保存**之前**读取快照令牌，成功保存同一工程/文件后才尝试有条件清理；查询失败、身份不确定、保存中快照变化或旧宿主没有新桥接能力时保留快照并最多提示一次，不退回旧无条件删除。新渲染器的自动恢复写入也只用新宿主暴露的`writeRecoverySnapshotIfCompatible`能力；旧宿主缺此能力时拒用旧无保护写入并给中英文告警。宿主受保护拒写亦只提示一次，不把拒写装作备份成功。
