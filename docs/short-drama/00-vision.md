# 00 · 产品愿景 (Vision)

> **本文档是项目的北极星**。后续所有功能取舍、技术选型、节奏判断，与本文档冲突时以本文档为准。
> **撰写立场**：用户为创业者，目标是个人 / 工作室自用的高质量高产出短剧系统，作为创业项目。

---

## 1 · 一句话定位

> **把 CanvasPro 改造成"以画布为核心的 AI 短剧生产系统"——把一部网文，一键变成一整部可发布的短剧。**

短剧 = 1-3 分钟的竖屏剧情视频，节奏快、爽点密、单集独立又串联成长篇。
本系统覆盖**从原著到成片的全流程**，输入小说/剧本，输出完整 MP4 + 剪辑工程。

---

## 2 · 为什么是现在

### 2.1 市场切片

- **短剧赛道 2025-2026 仍在爆发期**：抖音/快手/视频号付费短剧 GMV 持续增长，单部爆款营收百万级
- **传统短剧制作成本压不下来**：真人拍摄 + 演员 + 场地 + 后期，单集 5000-2 万元成本
- **AI 短剧已被验证可行**：Sora / 可灵 / 即梦 / Runway 的 i2v 能力已能产可看视频
- **但没有"一个人能闭环一部 30 集短剧"的工具**：
  - 通用 AI 视频生成器（Sora / Runway）—— 只做单镜头，没有项目管理、剧本管理、资产复用
  - 国产专业工具（万兴喵影、剪映）—— 偏剪辑后期，不管创作前期
  - 国产 AI 短剧平台（Toonflow / 海螺 / 妙鸭）—— 在试，但产品不闭环或竞品割裂
- **窗口期**：6-12 个月内市场会沉淀 1-3 个工具型赢家

### 2.2 我们的位置

CanvasPro 已经持有**两块关键资产**:

1. **成熟的无限画布引擎** —— Electron + Python 已跑通，处理大尺寸节点、媒体、缩放、协作不掉帧
2. **稳定的本地 AI 媒体管线** —— `server.py` 14 万行,生图/视频/音频/剪辑都已接通

业内同类产品**没有把"画布"作为创作核心**的——Toonflow 的画布是"工作台",CanvasPro 的画布是"创作媒介"。这是差异化基石。

## 3 · 用户画像

### 3.1 主用户：自用创作者（Owner-Operator）

- **谁**：独立创作者 / 1-3 人微型工作室
- **背景**：有内容判断力（看得懂剧本好不好、画面美不美）、不一定懂代码、追求产能与质量并重
- **现状**：
  - 在用 Midjourney + 剪映 + ChatGPT 拼凑流程,每集要 5-10 小时
  - 输出风格不统一,人物角色一致性差,故事节奏被工具碎片化
  - 月产 < 5 集成片
- **目标**:
  - 月产 30+ 集成片
  - 单集质量达可发布水准(GMV 能跑)
  - 不需要在 N 个工具间切换

### 3.2 次要用户(V2+ 扩展)

- **MCN/小型短剧公司**:需要团队协作、版本管理、对接平台 API
- **网文 IP 方**:批量改编自有 IP,需要项目级模板与资产复用
- **教学/培训**:把生产过程作为教学素材

> **MVP 阶段只服务主用户**。次要用户的需求理解但不实现。

## 4 · 产品价值主张

### 4.1 给主用户的三句话

1. **"输入你的小说,输出可发布的短剧。整部,不是单集。"**
2. **"画风、节奏、人物形象,从第 1 集到第 30 集保持一致。"**
3. **"你只负责审稿和把关,剩下的让 AI 跑。"**

### 4.2 量化承诺

| 指标 | 现状(用户拼工具) | CanvasPro 短剧版 |
| --- | --- | --- |
| 单集生产时长 | 5-10 小时 | 1-2 小时(其中 80% 是审稿等待) |
| 月产 | 3-5 集 | 30+ 集 |
| 角色一致性 | 30-60%(每集需重新对齐) | 95%+(项目级资产库) |
| 工具切换次数 | 5-8 个工具 | 1 个 |
| 上手时长 | N/A(自学) | < 1 天(画风+题材模板开箱即用) |

> 这些数字是"做到才有意义"的硬约束,不是营销话术。每条都对应阶段 A 的通过标准。

## 5 · 差异化:为什么是 CanvasPro 而不是别人

| 对手 | 他们做什么 | 缺什么 | CanvasPro 的回答 |
| --- | --- | --- | --- |
| **Sora / Runway** | 单镜头 i2v/t2v 质量高 | 没有剧本、项目、资产、剪辑 | 我们是上下游全包 |
| **剪映 / 万兴** | 剪辑端体验好 | 前端创作要靠自己 | 我们前端到后端一条龙 |
| **Toonflow** | 三层 Agent + 多 Skill 矩阵 | 画布弱、本地能力差、商业化不闭环 | **复用其框架,画布更强、本地化更深** |
| **海螺 / 妙鸭** | 单点能力强(语音 / 数字人) | 不组装成项目 | 我们是项目级 |
| **ChatGPT / Claude + MJ** | 灵活强大 | 切换成本高、无项目记忆 | 我们记住整个项目 |

**我们的护城河三件事**:

1. **画布作为创作主介质** —— 别人用对话框 + 表单,我们让用户在画布上看到整集的资产和分镜布局,所见即所得
2. **多角色 Agent + 大规模 Skill 库** —— 借鉴 Toonflow 的"决策/执行/监督"协作范式与 skill 矩阵,自主迭代
3. **本地化深度** —— Electron + 本地模型,数据不出本地、可离线运行、不依赖云供应商

> **实现口径（v0.2 补，须读）**："三层 Agent"/"fork" 在本文是**产品层概念**，不是工程实现承诺。按 `05-decisions.md`：D1 = **不 fork Toonflow 代码**，扩展 CanvasPro 自研 Agent；D3 = **单层 `agentRuntime` + skill 按 role 分组**模拟三层效果，不起三个进程。"fork" 仅指**范式与 skill 内容**借鉴后自主迭代。本文与 05 冲突时，实现以 05 为准。

## 6 · 系统边界

### 6.1 我们做什么(In Scope)

**核心**:
- 项目级生产:从输入(小说/剧本/创意)到输出(MP4 + 工程包)
- 三层 Agent 协作(ScriptAgent + ProductionAgent)
- 项目级资产库 + 衍生资产管理
- 画布作为生产主介质
- 多画风 + 多题材的 skill 库
- 本地模型 + 云端模型双轨

**支撑**:
- 模型供应商配置(项目级 + 全局级)
- 任务队列与异步生成
- 字幕、TTS、BGM、剪辑、导出
- 多集项目管理

### 6.2 我们不做什么(Out of Scope)

**永久不做**:
- 真人拍摄相关(灯光、机位、演员管理)—— 我们是 AI 路径
- 平台投放(自动发布到抖音 API)—— 法律灰色,留给运营工具做
- 通用绘图/通用视频生成—— 我们只服务短剧

**暂不做(后置到 V2+)**:
- 多人实时协作(目前是 single-user)
- 移动端 / Web 版(只做 Electron 桌面端)
- 跨语言(只做中文短剧,英文翻译留给翻译工具)
- AI 配音克隆(版权风险,暂不做)
- 自研生图/生视频模型(我们是应用层)

### 6.3 与 CanvasPro 原版的关系

CanvasPro 原版(自由画布模式)**继续保留**:
- 不删除任何现有功能
- 用 `projectType: freeform` 区分,新用户默认看到短剧入口
- 原画布用户的工程文件不受影响
- 共享底层引擎(渲染、媒体、AI 调用)

> 这是一次**功能扩展**,不是**重构替换**。两种模式共生。

## 7 · 核心非目标(Non-Goals)

> 这些事看起来很合理但**故意不做**,避免散光。

| 非目标 | 看起来该做但不做的原因 |
| --- | --- |
| **支持长视频(电影/电视剧)** | 短剧的节奏、爽点、单集独立性,与长视频是不同游戏。专精 |
| **做"傻瓜式一键生成"** | 我们的用户是创作者不是消费者,需要可控性、可干预、可调优 |
| **做云端 SaaS** | 创作者的素材是核心资产,数据本地化是诉求而不是缺点 |
| **做 PGC 内容平台** | 工具不下场做内容,避免与用户竞争 |
| **追求模型性价比** | 用户要的是质量与稳定,不是省钱 |
| **支持每一种新模型一上市就接** | 接了不调优 = 没接。每个模型上来都要 prompt 模板调优,资源有限优选稳的 |
| **过度抽象/插件化** | 我们不做平台,我们做产品。先做对,再考虑开放 |

## 8 · 成功标准

### 8.1 阶段 A(主干贯通)的成功

- ✅ 1 章网文(2000-5000 字)→ 1 集 90-180 秒成片
- ✅ 全程不崩,失败率 < 5%
- ✅ 单集生产时长 < 2 小时(含 AI 等待)
- ✅ 用户自己用着不想换工具

### 8.2 整体项目的成功(12 个月内)

- ✅ 用户自己产出 1 部完整 30 集短剧
- ✅ 1 部完整短剧在某平台投放且数据可见(任何水准的播放量)
- ✅ 月产能从 < 5 集稳定提升到 30+ 集

### 8.3 系统级的成功

- ✅ 任意一集重新打开,画布状态完全还原
- ✅ 项目导出后换台电脑重新导入,完全可用
- ✅ 升级版本后老项目不破坏

## 9 · 与 Toonflow 的关系

明确表态,避免后续模糊:

- **Toonflow 是参考实现**,不是依赖
- **范式 fork**:三层 Agent + Skill 矩阵 + 画布工作区,这些范式我们沿用
- **代码不直接复用**:Toonflow 是 TypeScript + Node.js + Express,CanvasPro 是 Python + Electron,**全部 Python 重写**
- **Skill 内容 fork**:Toonflow 的画风/题材 skill 文件是 Apache-2.0 + 补充商业条款,我们 fork 后**自主迭代**,不上游同步
- **数据库表名沿用**(`o_` 前缀):减少术语翻译成本,术语一致便于查文档
- **协议沿用**(socket 命名空间 + 事件名):前端组件迁移成本最低

**核心独立性**:
- 我们的画布是 CanvasPro 自己的,不复制 Toonflow 的画布
- 我们的本地模型管线是 CanvasPro 自己的,不依赖 Toonflow 的 Vercel AI SDK 范式
- 我们的剪辑/导出是 CanvasPro 自己的,不复制 Toonflow 的方案
- 我们的产品体验由我们自己定义,不锁死在 Toonflow 的 UI

## 10 · 创业项目的现实约束

### 10.1 团队规模

- **当前**: 1 个核心开发者 + AI 协作
- **3 个月内**: 不扩张,先打通主干
- **6-12 个月**: 视收入情况决定

### 10.2 资源约束

- **模型 API 成本**:GPT-4 / Claude / 视频模型 API 月支出可观,需建立成本监控
- **生图/视频任务等待**:用户审稿期间任务排队,UI 必须显示队列状态
- **本地存储**:一部 30 集短剧的素材包可达数十 GB,需提前规划本地存储与备份策略

### 10.3 收入路径(避免过早商业化)

- **阶段 A-B**:**不商业化**,自用 + 输出作品建立信誉
- **阶段 C-D**:开放 beta,小范围发邀请码,看付费意愿
- **阶段 E+**:订阅制 + 模板市场,但**不上 SaaS**(本地软件许可)

### 10.4 风险与对冲

| 风险 | 对冲 |
| --- | --- |
| 模型供应商 API 涨价/封号 | 多供应商接入 + 本地模型兜底 |
| AI 短剧赛道竞争激烈 | 画布差异化 + 本地化深度 |
| 长项目复杂度爆炸 | 每阶段都是完整切片,可独立止损 |
| 用户审美变化快(画风过时) | Skill 模板易于 fork 与迭代 |
| 法律/合规(版权、未成年人保护) | 输出物水印 + 用户协议明确创作者责任 |
