# 第十六批：原媒体任务中心的显式查询与结果取回

更新：2026-09-23。R03有限源码增量，**未运行验收**。沿用 `TaskCenterManager`、桌面 `MediaTaskQueue` 和原 `mediaTask:list/onUpdate`，不新造任务中心、持久队列、厂商客户端或自动重试器。

> 续接：本文描述的是**第16批当时**的内存查询与人工取回；第20批另加明确启用的本机持久摘要/只读历史查询，见 [media-task-history.md](media-task-history.md)。本批原有“没有持久日志”只指第16批交付时，不能用它否认后续源码，也不能把后续源码说成已运行验收。

## 已接入入口

- 原侧栏任务中心增加“刷新宿主记录”、任务ID输入、“查找任务”。本地任务卡增加“查找 / 取回”；`storySequenceExport` 显示“镜头顺序渲染（本地）”。原生成任务、定位文件、复制错误与已有取消入口保留。
- 刷新读取当前宿主最近最多500条，原列表仍最多保留120条、已完成分组仍显示前40条；查询区可以单独展示指定taskId，不被列表显示容量遮蔽。
- 更新后的宿主在原 `list` 请求上支持可选 `taskId`：直接从原内存Map取出对应快照，最多一条。查询超过最近500条的旧任务不必重跑。没有新增IPC或更换preload。
- 旧桌面忽略新字段时仍返回最近列表，前端只匹配确切taskId，绝不取第一条代替；查不到明确提示旧宿主范围/重启丢失记录，不解释为“未执行”或“未产出”。无桌面接口时明确禁用，不回退后端。
- 查询区显示任务ID、类型、原状态；已完成且符合白名单时显示可选中复制的只读本地路径及“确认取回到当前画布…”。进行中、失败、取消、未知、缺元数据或不支持的种类不创建素材。
- 查询/刷新不调用 `enqueue/cancel`，不请求AI，不重发任务；12秒查询超时只停止此次等待，不取消宿主工作。原取消行为未扩展，更不保证取消厂商执行/计费。

## 人工取回的范围

仅接入已逐一核对宿主返回契约的四类：

| kind | 结果 | 条件 |
| --- | --- | --- |
| storySequenceExport | source-video | 完成、success=true、明确本地MP4、正视频时长 |
| mediaClipExport | source-video | 同上，复用原视频剪辑结果 |
| videoReverse | source-video | 同上，复用原倒放结果 |
| audioCompose | source-audio | 完成、success=true、明确本地MP3；原返回可不含时长，显示未知而不捏造 |

不把缩略图、波形、未知kind、任意URL、厂商生成结果一律当成完整素材。只接受规范的 `output/` 虚拟路径；拒绝绝对/远程/反斜杠/编码/查询片段/路径穿越以及localPath与path不一致的结果。原任务中心其他种类的已有功能不被移除。

取回流程：
1. 用户先打开要接收结果的画布，在原任务中心查询任务。
2. 点击取回时捕获当前画布nodes对象，重新查询宿主、核对预览的任务/完成时间/路径/媒体元数据，并检查当前画布已有取回记录。
3. 明确确认任务ID、类型、路径及“加入当前画布的独立素材”。**不自动切回原画布、不覆盖原节点、不恢复镜头关联**。原nodeId只保存为来源线索，不据此推断工程归属；相同ID的其他画布也不借用。
4. 确认后再次只读查询；任务记录、目标画布或查询区生命周期改变则拒绝写入。单store同时只允许一个取回动作，不因连点生成多个查询/写入链。
5. 白名单构造媒体字段，复用原 `buildSourceMediaNodePayload/buildSourceAudioNodePayload`、安全放置、store.batch、选择和history commit，新建独立素材节点。只引用原文件，不复制字节、不重发原任务；节点挂载后的媒体加载/预览和可能的元数据/派生任务沿原机制。
6. 用户继续原工程保存。模型账号失效不阻止已有本地结果取回；应用/history不是磁盘保存回执。

## 来源与保存

新节点的 `mediaTaskRecovery` 保存版本1、taskId、kind、创建/完成/取回时间、原nodeId线索、本地路径。只复制所需字段，不复制原节点、请求payload、密钥、服务URL、任意参数、原任务result对象或厂商响应。没有伪造 `storySequenceOutput/storyMediaResult/mediaRefs`；工作室自动关联仍须原明确采纳链路。

同一画布已有同taskId/创建时间/kind/路径的本批取回记录时拒绝重复添加，JSON及原持久化清洗函数保留记录。此规则不识别原导出流程创建但没有取回标签的节点，也不跨画布去重；所以确认明确要求先核对原流程是否已经添加过相同文件。手工删除、撤销或移除标签后仍可能重复，不是全局幂等账本。

store.batch只合并通知，不是回滚事务；history更新失败时，若节点已写入则明确报告“已写入、待核对保存”，不假称回滚、不自动再添加。没有磁盘保存/重开运行证据。

## 竞态与既有逻辑保护

- 原任务中心启动/手动读取的列表不会覆盖读取期间收到的更新事件；新刷新或隐藏/清理使旧读取失效。事件版本记录超过1000项时清理并使在途刷新失效，不以丢失版本为由覆盖新事件。仅维护本页辅助状态，不是任务历史持久化。
- 查询区隐藏、输入改变等会使旧响应失效；旧启动列表错误也不覆盖新的查询反馈。快捷键在查询区隔离，路径使用只读textarea，不依赖 `window.prompt` 或剪贴板权限。
- 审阅发现第15批导出控制器之外，原 `mediaTaskService` 仍会按nodeId写通用生成状态。现对 `storySequenceExport` 跳过该通道；任务中心仍接收事件，结果由第15批画布/来源守卫写回或本批显式独立取回。避免同ID跨画布的状态误写。
- **没有全面重构其他旧种类的自动节点回写。** 普通媒体任务/厂商生成原自动更新、取消及缓存语义保留；本批新取回链的保护不能外推为所有旧自动生成已具备跨画布安全保证。

## 仍未实现／不能承诺

- 第16批宿主队列仍是原内存Map。窗口前端刷新后可查询仍存活的宿主记录，但宿主重启、崩溃、关闭应用后不保证存在；本批没有持久日志、历史备份导入或自动恢复执行。第20批的显式持久摘要不改变原队列的内存性质。
- 不扫描磁盘，不检查结果文件存在性、字节内容或哈希，不保证文件没被移动、删除、覆盖。只在宿主明确成功记录基础上创建引用；不是完成真实性审计或备份。
- 不自动恢复原工程、原剪辑、逐镜关联，也不把当前模型清单当成读取旧文件的前提。
- 不新增后台跨画布调度、厂商任务查询、远程媒体落地、可靠远端取消、批量取回或工程包。
- R01–R26仍保留；本批是R03部分能力，不是新版任务系统全部完成。
